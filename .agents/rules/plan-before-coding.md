Before implementing a non-trivial task:

1. Understand the user's requirements.
2. Inspect the relevant files.
3. Identify the components and services affected.
4. Explain the proposed solution.
5. List the files you intend to change.
6. Identify potential risks and edge cases.

Do not modify files until the user approves the plan.

If the task is trivial, such as correcting a typo, you may proceed
without a formal planning phase unless the user requests otherwise.

If you discover a problem that requires changing the approved scope,
stop and explain the issue before proceeding.
